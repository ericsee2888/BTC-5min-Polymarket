# Polymarket BTC 5分钟盘口策略下一步方案 v1

## 一、当前我们已经证明了什么

这轮 42 小时左右的数据采集和第一版早期诊断回测，已经能支持一个初步判断：

**BTC 5 分钟盘口里，价格源偏离信号不是纯噪音。**

当前最重要的发现是：

- 可用样本：`502` 个较完整的 5 分钟窗口。
- 如果 Binance 和 Coinbase 同时偏离目标价 `$50` 以上，并且只在开盘后 `60-180` 秒入场，样本约 `113-122` 笔。
- 这组信号胜率约 `78%-80%`。
- 如果阈值提高到 `$100`，样本只有 `24-25` 笔，但胜率约 `96%`。
- 这说明“多源价格穿越目标价”这条信号值得继续研究。

但这还不是完整交易策略。

当前回测还只是“方向诊断”，不是“真实可成交回测”。

## 二、当前还没有证明什么

这一步非常关键。

我们现在还没有证明：

1. 真实下单时能不能吃到回测里看到的价格。
2. 大金额下单会不会把盘口打穿。
3. 真实可成交数量是多少。
4. bid / ask 深度够不够支撑每笔 `50 / 100 / 500 / 1000 USDC`。
5. 止盈价 `0.75` 是否真的有足够买盘可以卖出。
6. 订单簿是否存在文章里说的“聪明钱确认信号”。
7. 真实 taker 交易是否会因为延迟、滑点、部分成交而把优势吃掉。

所以现在不能直接进入实盘。

如果现在贸然实盘，最大风险不是方向错，而是：

**信号对，但成交不到；或者小金额能成交，大金额成交后价格完全变形。**

## 三、下一步总目标

下一步目标不是继续证明“方向有没有用”。

下一步目标应该改成：

**验证这个方向信号是否能转化成真实可成交的交易策略。**

这要分三层推进：

1. 补订单簿采集。
2. 做真实可成交回测。
3. 再决定是否进入纸上交易或极小金额实盘观察。

## 四、阶段 1：补订单簿采集

### 目标

在现有价格采集脚本基础上，新增 Polymarket CLOB 订单簿快照。

每条样本至少要补：

- `up_best_bid`
- `up_best_ask`
- `down_best_bid`
- `down_best_ask`
- `up_ask_depth_0_55`
- `up_ask_depth_0_60`
- `up_ask_depth_0_65`
- `up_bid_depth_0_70`
- `up_bid_depth_0_75`
- `down_ask_depth_0_55`
- `down_ask_depth_0_60`
- `down_ask_depth_0_65`
- `down_bid_depth_0_70`
- `down_bid_depth_0_75`
- `book_fetch_latency_ms`
- `book_error`

### 为什么要这么做

当前回测只知道某个时点的 `Up` 或 `Down` 价格大约是多少，但不知道：

- 这个价格能买多少。
- 买 `100 USDC` 会不会扫到下一档。
- 买 `1000 USDC` 会不会把价格从 `0.50` 打到 `0.65`。
- 提前止盈时，`0.75` 附近有没有足够买盘接货。

没有订单簿，就无法回答真实资金容量。

### 推荐采样频率

先不要全量高频抓完整盘口。

第一版建议：

- 每 `2` 秒继续抓价格。
- 每 `2` 秒抓当前窗口 Up / Down 两个 token 的订单簿。
- 只保留前 `10-20` 档。
- 先跑 `24` 小时。

这样能先判断容量和滑点，不会一开始就把数据量放得太大。

## 五、阶段 2：真实可成交回测

订单簿采集完成后，回测要从“每股收益”升级成“固定下单金额”。

建议先测 4 个金额：

- `50 USDC`
- `100 USDC`
- `250 USDC`
- `500 USDC`

每笔交易要模拟：

1. 在触发信号时，以 taker 方式扫对应方向 ask。
2. 按订单簿逐档成交，而不是假设全都在一个价格成交。
3. 扣买入 taker fee。
4. 如果触发止盈，以 bid 逐档卖出。
5. 扣卖出 taker fee。
6. 如果没止盈止损，则持有到结算。

### 回测输出必须包含

- `trade_count`
- `fill_success_rate`
- `avg_entry_price`
- `avg_exit_price`
- `avg_slippage`
- `avg_fee`
- `avg_net_pnl`
- `median_net_pnl`
- `max_drawdown`
- `capacity_limit`
- `worst_fill_case`

这一步做完，才能判断这条策略到底是：

- 只能做几十 USDC 的小策略；
- 可以做到几百 USDC；
- 还是具备继续扩容的可能。

## 六、阶段 3：订单簿确认信号

文章里提到订单簿失衡确认，这一层我们还没验证。

下一版可以加两个简单信号：

### 1. 深度失衡

定义：

- `up_bid_depth_near_mid / up_ask_depth_near_mid`
- `down_bid_depth_near_mid / down_ask_depth_near_mid`

观察：

- 当价格源信号指向 UP，同时 UP 买盘深度增强，胜率是否提升。
- 当价格源信号指向 DOWN，同时 DOWN 买盘深度增强，胜率是否提升。

### 2. 盘口价格确认

定义：

- 价格源已经明显偏向 UP，但 UP 价格仍在 `0.50-0.60`。
- 或价格源已经明显偏向 DOWN，但 DOWN 价格仍在 `0.50-0.60`。

这类情况可能才是真正的滞后机会。

如果市场已经把 UP 打到 `0.80`，即使方向对，也可能没有足够收益空间。

## 七、阶段 4：纸上交易

如果真实可成交回测仍然为正，再进入纸上交易。

纸上交易不是再做历史回测，而是实时生成“应该下单”的日志。

每次触发信号时，记录：

- 当前窗口
- 触发时间
- 方向
- 目标价
- Binance / Coinbase / Chainlink 偏离
- 应买 token
- 模拟下单金额
- 模拟成交均价
- 模拟止盈 / 止损 / 结算结果
- 模拟净收益

建议纸上交易至少跑：

- `3` 天
- 或至少 `100` 笔模拟交易

达标后再考虑极小金额实盘。

## 八、是否要恢复采集

当前价格采集已经暂停。

我的建议是：

**先不要简单恢复旧采集。**

下一步应该先升级采集脚本，把订单簿一起写进去，然后再开新一轮 24 小时采集。

否则继续采旧字段，边际价值已经变低。

## 九、建议执行顺序

### 第一步

新增订单簿采集脚本或扩展现有采集脚本。

产出：

- `polymarket_crypto_5m_btc_price_book_samples_v1.csv`
- `polymarket_crypto_5m_btc_price_book_samples_v1.jsonl`

### 第二步

跑一轮 `2-4` 小时 smoke test，确认：

- token id 映射正确；
- Up / Down 两边订单簿都能抓到；
- 深度字段不是空；
- 文件大小可控。

### 第三步

跑一轮 `24` 小时正式采集。

### 第四步

做真实可成交回测 v2。

先测：

- `$50` 偏离阈值
- `$75` 偏离阈值
- `$100` 偏离阈值

资金规模先测：

- `50 USDC`
- `100 USDC`
- `250 USDC`
- `500 USDC`

### 第五步

如果 v2 仍然显著为正，再进入纸上交易。

## 十、当前结论

这条线值得继续。

但下一步的重点不再是“信号准不准”，而是：

**信号出现时，盘口上有没有足够便宜、足够深的真实流动性。**

如果有，这条策略可能是一个真实可推进的 Polymarket crypto 微观结构策略。

如果没有，它就只是一个看起来很漂亮、但实盘容量很小的信号。
